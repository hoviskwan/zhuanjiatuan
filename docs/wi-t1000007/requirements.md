# 客户跟进管理 · 需求基线

> Work Item：wi-t1000007 · 阶段：requirements
> 来源标注约定：**用户明确提出** 为用户请求中的原始描述；**推荐基线** 为闭合核心目标所必需、可逆且可观察的最小补充，已纳入本次验收；**未规定** 为不影响核心验收、本次不做决定的事项（见第 6 节）。

## 1. 目标

交付一个"客户跟进管理"React 应用，让使用者在一处完成客户的查看与筛选、按销售阶段跟进客户、记录沟通过程。

用户明确提出：

- 应用形态：React 应用，数据使用本地状态管理。
- 三个界面模块：客户列表、销售阶段看板、客户详情页。
- 客户列表支持搜索、标签筛选和阶段筛选。
- 销售阶段看板支持拖拽客户切换销售阶段。
- 客户详情页可以新增跟进记录、设置下次联系时间和负责人，并用时间线展示历史沟通。

## 2. 范围与模块

### 2.1 客户列表

- 展示客户清单，每条客户至少展示其名称。
- 提供搜索输入：输入关键词后，列表仅保留匹配的客户。匹配范围为客户名称（**推荐基线**：名称包含该关键词）。
- 提供标签筛选与阶段筛选，条件来自客户自身的标签与销售阶段。
- 搜索与各筛选条件可同时生效：列表仅显示同时满足全部已选条件的客户。
- 无任何客户满足条件时，列表显示无结果反馈（有明确的无结果提示，不是空白或报错）。

### 2.2 销售阶段看板

- 按销售阶段分列展示客户卡片，每个客户出现在其当前阶段对应的列中。
- 支持将客户卡片拖拽到其他阶段列；拖拽完成后，该客户的销售阶段更新为目标列对应的阶段。
- 阶段变更在看板与客户列表之间保持一致：同一客户在两处显示的阶段相同（同一数据源驱动）。
- 看板使用的阶段集合为固定默认集合（**推荐基线**：待跟进、需求沟通、方案报价、商务谈判、已成交，共五列）。是否允许自定义阶段为**未规定**事项，本基线不含自定义阶段功能。

### 2.3 客户详情页

- 展示客户当前信息：销售阶段、标签、下次联系时间、负责人。
- 新增跟进记录：录入跟进内容并保存后，该记录进入该客户的历史沟通。
- 时间线：按记录时间展示该客户全部历史跟进记录，每条包含记录内容与记录时间（**推荐基线**：由早到晚排序）。
- 可设置并修改客户的下次联系时间与负责人；设置后详情页展示所设值。
- 标签维护（**推荐基线**，为闭合"标签筛选"所必需）：以自由文本为客户添加、移除标签，客户可持有多个标签。
- 详情页是否提供销售阶段编辑入口为**未规定**事项；本基线中阶段变更入口为看板拖拽（用户明确提出）。
- 跟进记录的编辑、删除，以及下次联系时间的到期提醒，均为**未规定**事项，本基线不含。

## 3. 客户数据与本地状态

客户实体包含以下数据：

| 数据项 | 说明 |
| --- | --- |
| 名称 | 客户标识，列表与详情页展示、搜索匹配对象 |
| 销售阶段 | 客户当前所处阶段，驱动看板列归属与阶段筛选 |
| 标签 | 客户可持有多个自由文本标签，驱动标签筛选 |
| 下次联系时间 | 详情页可设置、修改的时间值 |
| 负责人 | 详情页可设置、修改的文本值 |
| 跟进记录列表 | 每条含记录内容与记录时间，按时间线展示 |

数据管理（用户明确提出）：全部数据使用本地状态管理。任何新增或修改在同一会话内即可通过相应界面读回（如新增跟进记录后时间线可见、拖拽后列表阶段可见）。刷新或重新打开应用后的数据保留（持久化）为**未规定**事项：本基线不承诺跨会话持久化，也不指定任何存储技术。

## 4. 核心行为与规则

- R1：客户列表的搜索与标签、阶段筛选可组合生效，仅显示同时满足全部条件的客户；无匹配时显示无结果反馈。
- R2：看板拖拽客户卡片到其他阶段列即切换该客户销售阶段，且列表与看板数据保持一致。
- R3：详情页新增的跟进记录立即进入该客户时间线，与历史记录一并按时间展示。
- R4：详情页可设置、修改并展示客户的下次联系时间与负责人。
- R5：客户可维护标签（推荐基线），标签可作为列表筛选条件（用户目标）。

## 5. 验收场景

### AC-01：用户可在客户列表中搜索并按标签、阶段筛选客户

- 验收条件：客户列表展示客户；输入搜索关键词或选择标签、阶段筛选条件后，列表仅显示同时满足全部已选条件的客户；无满足条件的客户时给出无结果反馈。作为标签筛选的数据来源，用户可在客户详情页为客户添加或移除标签（推荐基线）。
- 入口类型：用户界面
- 验证动作：
  1. 打开客户列表，确认列表展示客户；
  2. 进入任一客户详情页，为该客户添加标签"重点客户"，确认标签显示在详情页；
  3. 返回客户列表，在标签筛选中选择"重点客户"，观察列表；
  4. 清除标签筛选，在搜索框输入该客户名称中的关键词，观察列表；
  5. 清除搜索，在阶段筛选中选择某一销售阶段，观察列表；
  6. 同时选择标签筛选与阶段筛选，观察列表；
  7. 在搜索框输入不存在的关键词，观察列表。
- 预期结果：步骤 2 中标签显示在详情页；步骤 3 仅显示带"重点客户"标签的客户；步骤 4 仅显示名称包含该关键词的客户；步骤 5 仅显示所选阶段的客户；步骤 6 仅显示同时满足两个条件的客户；步骤 7 显示无结果反馈，不出现报错或空白。
- 证据类型：interaction

### AC-02：用户可在看板通过拖拽切换客户销售阶段

- 验收条件：看板按销售阶段分列展示客户卡片，每个客户出现在其当前阶段列；将客户卡片拖拽到其他阶段列后，该客户销售阶段更新为目标列阶段，且客户列表中的阶段信息同步更新。
- 入口类型：用户界面
- 验证动作：
  1. 打开销售阶段看板，确认各阶段列中展示了处于该阶段的客户；
  2. 将某客户卡片拖拽到另一个阶段列并松开；
  3. 打开客户列表，查看该客户显示的阶段（或在阶段筛选中选择新阶段，确认该客户出现）。
- 预期结果：步骤 2 后该卡片出现在目标列、从原列消失；步骤 3 中该客户在列表显示为新阶段，且列表阶段筛选结果与看板一致。
- 证据类型：interaction

### AC-03：用户可在详情页新增跟进记录并通过时间线查看历史沟通

- 验收条件：客户详情页以时间线展示该客户全部历史跟进记录（含内容与记录时间，按时间排序）；用户新增一条跟进记录后，该记录立即出现在时间线中。
- 入口类型：用户界面
- 验证动作：
  1. 打开某客户详情页，查看时间线中的历史跟进记录；
  2. 录入一条新的跟进内容并保存；
  3. 再次查看该客户时间线。
- 预期结果：步骤 1 中时间线按时间展示已有记录（含内容与时间）；步骤 3 中新增记录出现在时间线中，内容与录入一致。
- 证据类型：interaction, runtime-render

### AC-04：用户可在详情页设置下次联系时间与负责人

- 验收条件：客户详情页可设置并修改客户的下次联系时间与负责人，设置后详情页展示所设值。
- 入口类型：用户界面
- 验证动作：
  1. 打开某客户详情页，设置该客户的下次联系时间与负责人并保存；
  2. 查看详情页当前展示（或重新进入该客户详情页）；
  3. 修改其中一项（如下次联系时间）并保存，再次查看。
- 预期结果：步骤 2 中详情页显示所设的下次联系时间与负责人；步骤 3 中显示修改后的值。
- 证据类型：interaction

## 6. 未规定事项

以下事项本次不做决定，不纳入验收；如后续需要，应在对应阶段另行确认：

- 刷新或重新打开应用后的数据持久化（用户明确要求本地状态管理，本基线仅承诺会话内可读回）。
- 负责人的取值来源（本基线按自由文本录入处理，属推荐基线）。
- 下次联系时间的到期提醒行为。
- 跟进记录的编辑与删除。
- 客户是否包含名称之外的业务字段（如公司、联系方式）；本基线仅定义名称、销售阶段、标签、下次联系时间、负责人、跟进记录。
- 用户角色、权限与多使用者区分。
- 部署目标与运行环境。
